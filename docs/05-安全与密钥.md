# 安全与密钥

## 一、密钥到底存在哪

| 方案 | 存放位置 | 明文风险 | 适用 |
|---|---|---|---|
| **分片混淆**（默认） | `CodexHome\*.dat` | 不是明文，但可被还原 | 想省事、能接受"物理接触=可能泄露" |
| **官方账号登录** | `CodexHome\auth.json` | 明文 token（官方 CLI 行为） | 用官方账号、不想管密钥 |
| **BitLocker To Go** | 整盘加密 | 看系统解锁策略 | 最稳妥，需要 Windows 专业版 |
| **不放密钥** | 每次手动登录/输入 | 无 | 最安全，最麻烦 |

分片算法（见 `02-原理与设计.md` 第五节）：按字节切 3 段，每段独立与固定掩码
`codex-portable-2026` 循环 XOR，各自 Base64。

**必须清楚的三件事**：

1. **这是混淆，不是加密。** 掩码就写在脚本里（因为启动器要能还原），
   所以拿到 U 盘 = 拿到分片 + 拿到算法 = 可以还原出密钥。
2. 它防的是"**没打算偷你东西的人随手看到一串 sk- 开头的字符**"，
   比如把 U 盘借给别人拷文件时被翻到。
3. 想真正安全，只有两条路：**别把密钥放盘上**，或者**整个盘加密**。

## 二、更安全的做法（推荐组合）

1. **用可吊销、有额度上限的 Key**。哪怕泄露了，损失可控（去服务商后台吊销重发）。
2. **U 盘开 BitLocker To Go**：Windows 专业版自带，右键 U 盘 → 启用 BitLocker，
   设一个密码。这样物理接触也拿不到东西。
   （注意：BitLocker 加密的盘在别人电脑上需要输密码，会牺牲一点便利性。）
3. 公用电脑上**用完就跑一次「清理本机缓存」**，并确认 `auth.json` 已删除
   （正常退出时会自动删）。
4. 不要把 U 盘的分片文件（`*.dat`）和 `auth.json` 拷贝到别的地方，更不要提交到 Git。

## 三、想换成自己的掩码

掩码不是秘密，但换成自己的能防"照抄脚本的人顺手解别人的盘"：

1. 改启动器里这一行（三个 `launch-*.ps1` 都要改）：
   `$mask = [Text.Encoding]::ASCII.GetBytes("codex-portable-2026")`
2. 重新生成分片，生成时用同一个掩码：
   `python tools/mkshards.py -H E:\CodexHome --mask 你的新掩码`
   （`CodexHome\set-api-key.ps1` 也支持 `-Mask` 参数，两个工具的算法一致，都带自校验）

## 四、本仓库的隐私承诺

- 不包含任何密钥、令牌、账号信息或对话记录（`.gitignore` 已排除，源码里也没有）。
- 所有脚本都是**纯本地文件操作**，不联网、不上报。唯一会联网的是装配脚本
  在你主动加 `-Download` 时去上游下载程序。
- 「收集本机环境档案」采集的内容**只写回你自己的 U 盘**：用户名打码、
  机器序列号只存哈希、不读任何个人文件，测速用的临时文件跑完即删。
- 如果你 fork 这个项目，**提交前请确认**：
  `git status` 里没有 `*.dat` / `auth.json` / `sessions/` / 程序目录。
